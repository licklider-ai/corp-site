# Repository work

Read `CONTRIBUTING.md` and the applicable policy linked from `README.md` before
editing. Public content follows `docs/publication-architecture.md`; product and
agent documentation also follows `docs/agent-readable-documentation.md`.

## Blog tasks only

For any Blog commission, outline, draft, revision, review, or Blog-specific site
integration, read `docs/blog/README.md` and follow `docs/blog/WRITE.md` before
drafting. This trigger applies regardless of where the draft is stored or whether
the public Blog routes exist. Ordinary Research, Engineering, News, Docs, homepage,
and product work does not inherit Blog's audience, article structure, or cadence.

The Blog policy defines editorial decisions; the writing procedure executes it.
Neither changes upstream product/scientific authority or authorizes publication.

## Every content change

Read docs/content-workflow.md for a new article, a substantive update or a change
to product claims, availability or documentation. Run the existing content:impact
command against the actual PR base; inspect its candidate affected surfaces and
update those whose meaning changed. Shared site facts and registries remain the
source for generated views. The impact report identifies work to inspect; it is
not evidence that the semantics were reviewed or permission to publish.

Lead with concrete user value and supported achievements. Abstract unnecessary
production implementation details without withholding the basis of the claim.
Follow CONTRIBUTING.md for task-based naming and material provenance; required
instruction file names are compatibility, not promotional branding.

Complete the authorized update through build and production confirmation under
docs/deployment.md. Do not change article dates for an operational-only rebuild.
